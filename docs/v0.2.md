# v0.2: reliable acquisition, replay and artifact audits

This release focuses on reproducibility and honest numerical results. It does
not change Fisher definitions, probability normalization, support semantics or
the inference contract. Package version is `0.2.0`; artifact schemas remain `1.0`.

## Scope and acceptance

| Change | Acceptance |
| --- | --- |
| Backward derivatives | Explicit backward and automatic upper-bound stencils match independent closed-form derivatives, including both h and h/2. |
| Acquisition plan | Counts actual stencil points at each center, multiplied by repeats, cases and provider requests per point; invalid counts are refused and excess live budgets cause no provider call. |
| Numerical status | Unstable or conditional derivatives cannot produce an `ok` dependent Fisher quantity; missing captures and instability have distinct capability reasons. |
| Replay | Requires exact repeats, validates declared source identity and available selected request fingerprints, and never falls back to a live provider. |
| Capture roles | TypeSafe records preserve center and stencil roles, including failures. |
| Artifact audit | Missing, malformed, incomplete, escaped-path or changed checksum evidence fails with code 2; audits write nothing. |
| Reports | Save a new analysis revision and checksum coverage for its artifacts; previous metrics are retained. |

Analytically computed system information can remain valid independently of a
numerically unstable node estimate. A redundancy comparison that depends on
such a node estimate must still refuse it. Diagnostic values may be retained
with non-`ok` status; consumers must use the status and reason, not only a number.

## Migration from v0.1

1. Revalidate budgets. The ticket example with two parameters and three repeats
   makes `3 × (1 + 2 × 4) = 27` batched evaluations before retries. Boundary
   stencils may require fewer points. The old estimator displayed 11.
2. Request only recorded repeats when replaying old captures. A missing repeat
   now fails rather than silently copying repeat zero. Old TypeSafe captures
   with incorrectly recorded stencil roles need reacquisition for exact replay.
3. Review any consumer that treats Fisher sub-results as usable without checking
   their status. Unstable and conditional inputs now propagate their status.
4. Audit runs with `uv run jevometry verify RUN_DIRECTORY --json`. Older indexes
   may omit provider configuration, questions, inference or analysis revisions.
   This is reported as incomplete evidence. The audit never repairs it.

Reanalyze existing runs that used explicit backward stencils or automatically
switched to backward at an upper bound. v0.1 ordered the near/far negative
offsets incorrectly. For the linear family `q=(0.5+0.1x, 0.5-0.1x)` at `x=0`,
the exact Jacobian is `(0.1, -0.1)` and Fisher information is `0.04`; the old
backward computation produced `(0.35, -0.35)` and `0.49`. Its h/h2 stability
check could still pass because both scales shared the error. Captures at valid
stencil points can be reused for a new analysis; previously saved metrics must
not be interpreted as corrected measurements.

Custom stencil scales above one now use the effective larger step for bound
checks. A large step with no legal direction is unavailable rather than sampled
outside the declared parameter domain. Default h/h2 direction selection is
preserved; shrinking an unavailable nominal stencil is not an adaptive feature
of this release.

After independently reviewing an older run, an owner can explicitly establish
a new checksum baseline using `RunStore.load(Path("RUN_DIRECTORY")).finalize_checksums()`.
That records the files as they exist now; it cannot prove they were unchanged
since the original capture. Keep the old index separately if historical
verification is needed.

The Python `verify_checksums` function now raises `ValueError` for missing,
empty or invalid indexes. The CLI uses a structured audit instead of treating
missing evidence as successful verification.
